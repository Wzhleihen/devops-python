## Context

当前仓库以学习练习为主，存在按日期与按主题并行的目录组织方式。随着内容积累，用户在回看章节练习、定位历史学习记录时需要在多套路径中切换，增加检索成本。当前约束明确：保留中文章节顶层目录，不调整章节内部文件，仅进行顶层归档与 daily 体系建设。

## Goals / Non-Goals

**Goals:**
- 建立稳定、可长期扩展的顶层结构：`归档` + `daily` + 中文章节目录。
- 将历史日期目录统一收拢到 `归档/2025`，消除日期目录散落问题。
- 为后续学习沉淀预留统一入口（`daily/dayxx.md`）。
- 维持学习中断最小化：章节目录及其内部文件不改动。

**Non-Goals:**
- 不重构章节内部目录结构（如 `notes/practice/answers`）
- 不改动现有脚本与 notebook 内容
- 不引入新的构建、测试或自动化流水线

## Decisions

1. **采用“顶层轻量重构”而非“全仓深度重构”**
   - 决策：仅调整日期目录归档与新增 daily，不触及章节内部。
   - 原因：学习仓库优先保证连续性与低风险；避免大量路径变更导致 notebook 失效。
   - 备选：一次性重构全部章节内部结构；因风险高且投入大，暂不采用。

2. **保留中文章节目录作为主入口**
   - 决策：继续使用 `07_面向对象`、`文件IO`、`序列化与反序列化`、`正则表达式`。
   - 原因：符合用户检索习惯，降低认知切换成本。
   - 备选：统一英文章节目录；与当前使用习惯冲突，暂不采用。

3. **使用 `归档/2025` 集中管理日期目录**
   - 决策：全部 `2025-xx-xx` 目录迁入归档；修正异常命名 `20225-12-04`。
   - 原因：统一时间线资料入口，减少顶层噪音。
   - 备选：保留原地并仅在 README 建索引；可行但长期可维护性较差。

4. **daily 先建入口、后定模板**
   - 决策：先创建 `daily/`，暂不强制 day 内容模板。
   - 原因：用户明确希望后续再细化 daily 规划。
   - 备选：立即批量生成 day01/day02；与用户当前节奏不一致，暂不采用。

## Risks / Trade-offs

- [日期目录迁移后旧路径引用失效] → 通过“仅迁移日期目录、章节目录不动”降低影响；后续在 daily 或 README 建立映射说明。
- [归档后短期适应成本] → 通过稳定顶层规则（归档/章节/daily）换取长期检索收益。
- [daily 未立即模板化导致风格不统一] → 后续单独定义 day 模板并补齐前几篇。
