## Context

当前仓库在推进学习自动化（day 生成、练习生成、能力评估）时，任务分散在不同 change 的 `tasks.md` 中，缺少统一汇总视图。执行者难以快速判断“还剩什么、先做什么、是否阻塞”。本设计提供一个面向 change 的任务清单汇总能力，以低侵入方式复用既有 OpenSpec 任务格式。

## Goals / Non-Goals

**Goals:**
- 提供结构化任务清单汇总：状态统计、阶段分组、依赖提示。
- 输出可直接用于执行的下一步建议顺序。
- 增加最小一致性校验（编号、状态、依赖引用）。

**Non-Goals:**
- 不改动 OpenSpec 核心任务语法。
- 不引入新任务编排系统。
- 不改变已有 change 的业务语义，仅增强可观测性。

## Decisions

1. 以 `tasks.md` 作为唯一事实源。
   - 原因：当前流程已稳定使用复选框任务格式，兼容性最高。
   - 备选：维护额外 JSON 索引；放弃，避免双写漂移。

2. 按“流水线阶段”做规则化分组。
   - 分组：变更检索与标准化、day 生成、练习生成、能力评估、质量校验与集成。
   - 原因：与现有学习自动化流程一致，便于执行。
   - 备选：纯编号顺序；可读性不足。

3. 下一步建议采用“未完成 + 依赖已满足”的优先规则。
   - 原因：可直接落地执行，避免人工判断阻塞。
   - 备选：仅按编号推荐；遇依赖时误导风险较高。

4. 输出格式采用 Markdown + 机器可读块（可选 JSON）。
   - 原因：人读与自动处理兼容。
   - 备选：仅 JSON；对日常阅读不友好。

## Risks / Trade-offs

- [任务文本不规范] → 增加解析容错并在报告中标注“未识别项”。
- [依赖关系缺失] → 回退为编号顺序建议并提示人工补依赖。
- [不同 change 任务粒度差异] → 输出统计时同时展示“任务总数/完成率/阻塞数”以降低偏差。
