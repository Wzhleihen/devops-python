## Context

你希望把学习仓库从“人工复盘”升级为“自动学习教练”：每次代码变更都能自动生成 day 内容，并产出针对练习来持续提升开发水平。仓库已有 `daily`、`归档`、章节目录与 day 模板基础，具备落地自动化流水线的前提。

## Goals / Non-Goals

**Goals:**
- 构建统一流水线：变更检索 → day 生成 → 练习生成 → 能力评估。
- 保证输出可执行：每次生成都包含章节回链、练习验收标准、下一步建议。
- 支持增量运行：仅处理新变更，避免重复覆盖历史内容。
- 保证质量可验证：编号连续、路径有效、字段完整、结果可审阅。

**Non-Goals:**
- 不修改章节目录中已有代码逻辑。
- 不引入复杂在线服务或外部数据库（优先本地文件驱动）。
- 不在首版实现多模型编排或复杂可视化面板。

## Decisions

1. **采用“文件驱动的本地流水线”**
   - 决策：以本地 JSON/Markdown 中间产物作为状态与结果存储。
   - 原因：学习仓库轻量可控，便于调试和追踪。
   - 备选：引入数据库与服务化；复杂度过高，暂不采用。

2. **增量处理优先，历史回填作为已完成基线**
   - 决策：以最近处理游标为边界，只处理新提交。
   - 原因：避免重复生成 day 与练习，降低噪音。
   - 备选：每次全量重算；成本高且容易改写历史结论。

3. **练习生成分三级（基础/进阶/迁移）**
   - 决策：每次变更至少生成 1 题，可扩展至 3 题并附验收标准。
   - 原因：兼顾即时反馈与能力拉伸。
   - 备选：仅固定一题；提升效率但成长维度不足。

4. **能力评估采用规则分 + 趋势分离**
   - 决策：先用规则评分（章节覆盖、复杂度、错误修正质量）并输出趋势；后续再引入模型评分。
   - 原因：先保证稳定与可解释。
   - 备选：直接模型评分；早期波动大且难解释。

## Risks / Trade-offs

- [提交信息稀疏导致 day 内容泛化] → 结合文件路径与历史模板生成结构化占位，并支持人工补齐。
- [自动练习质量不稳定] → 强制每题包含验收标准、示例输入输出与难度标签。
- [增量游标错误导致漏处理/重处理] → 记录处理日志与回滚机制，支持按日期重跑。
- [评分主观性争议] → 输出评分依据字段，避免黑盒分数。
