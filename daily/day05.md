## 📌 今日内容（代码在做什么）
1. `filter(None, ...)`：验证 truthy 保留、falsy 过滤。  
2. `filter(lambda ...)`：按条件筛选特定元素。  
3. `map(lambda ...)`：执行批量映射变换。  
4. `zip(...)`：把多个序列按位打包，用于字典构造。  
5. `counter(base)`：通过 `nonlocal` 实现可持续自增闭包。

## 🧠 核心知识（底层原理）
- `filter` 与 `map` 返回迭代器，消费后需要重建。  
- `zip` 会按最短序列停止，天然带截断行为。  
- 闭包是“内部函数 + 外层变量环境”的组合体。  
- 在内部函数修改外层变量时，必须显式声明 `nonlocal`。

## 💻 关键代码（精简 + 行为解释）
```python
def counter(base):
    def inc(step=1):
        nonlocal base
        base += step
        return base
    return inc

f = counter(10)
print(f())  # 11
print(f())  # 12
```

### 行为解释
- `counter(10)` 返回携带私有状态 `base` 的函数对象。  
- 每次调用 `f()` 都在上次状态上继续累加。  
- `nonlocal` 确保修改的是外层 `base`，不是新建局部变量。

## ⚠️ 问题 / 坑（至少一个错误案例）
### 案例：闭包中遗漏 `nonlocal base`
- 错误现象：在 `base += step` 处触发未绑定变量错误（典型 `UnboundLocalError`）。  
- 证据位置：`归档/2025/2025-12-03/dmeo02.ipynb`（`counter` 讲解单元中明确说明“不加 nonlocal 会报错”）。  
- 根因：函数内有赋值时，解释器将变量判定为局部变量；读取时尚未初始化。  
- 修正：在内部函数声明 `nonlocal base`。  
- 防再犯规则：闭包里只要“修改外层变量”，先检查并声明 `nonlocal`。
