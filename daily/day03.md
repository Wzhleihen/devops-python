## 📌 今日内容（代码在做什么）
1. `selection_sort_v1`：每轮选最小值放前面，输出升序。  
2. `bubble_sort_v1`：相邻交换做降序，并用 `swapped` 实现提前结束。  
3. `selection_sort_v2`：每轮选最大值放前面，输出降序。  
4. `selection_sort_v2`（统计版）：输出 `(arr, count_iter, count_swap)`。  
5. `selection_sort_v3`：进入双向选择（同时处理 max/min）实验阶段。

## 🧠 核心知识（底层原理）
- 冒泡排序可通过“本轮是否发生交换”判断是否可提前结束。  
- 选择排序要确认极值，通常仍需扫描剩余区间。  
- `count_iter` 与 `count_swap` 能帮助区分“比较成本”和“交换成本”。  
- 双向选择排序的难点是：先交换最大值后，最小值索引可能失效，需要重映射。

## 💻 关键代码（精简 + 行为解释）
```python
def selection_sort_v2(arr):
    length = len(arr)
    count_iter = 0
    count_swap = 0

    for i in range(length - 1):
        max_index = i
        for j in range(i + 1, length):
            count_iter += 1
            if arr[j] > arr[max_index]:
                max_index = j
        if i != max_index:
            arr[i], arr[max_index] = arr[max_index], arr[i]
            count_swap += 1

    return arr, count_iter, count_swap
```

### 行为解释
- 每轮在未排序区间找最大值放到当前位置。  
- 在归档样例 `[9,6,1,3,4]` 中，输出 `([9,6,4,3,1], 10, 1)`，体现“比较多、交换少”。

## ⚠️ 问题 / 坑（至少一个错误案例）
### 案例：v3 实验阶段内核崩溃
- 错误现象：Notebook 出现 `The Kernel crashed while executing code...`。  
- 证据位置：`归档/2025/2025-11-29/sort.ipynb`（`selection_sort_v3` 前后单元）。  
- 根因：双向选择里最大值交换后，最小值索引更新链路不完整，导致状态调试复杂、执行不稳定。  
- 修正：
  1. 先固定 v2 正确版本作为基线；
  2. v3 拆分为“先 max 再 min”的两步实现；
  3. 每轮增加索引合法性断言与最小样例回归。
- 防再犯规则：复杂排序改造必须“先保正确，再做合并优化”。
